# 写作偏好学习

在当前工作区内执行，遵守工作区已有的代理说明和文件保护规则。完整读取 [写作偏好规则](references/preference-lifecycle.md)，再按用户指令选择模式。

## 先适配工作区

按以下顺序定位输入和输出，不要求项目使用固定目录名：

1. 优先使用用户明确给出的项目、稿件和偏好文件。
2. 其次使用当前工作区已有约定，例如 `05_内容草稿/`、`写作偏好/`、`00_个人背景/写作偏好/`。
3. 再按文件语义查找同一选题、平台和内容形式的 AI 初稿与用户编辑稿，例如 `*AI初稿*`、`*AI草稿*`、`*本人编辑稿*`、`*用户修改稿*`。
4. 只在当前工作区内查找，不跨项目扫描。存在多组候选且无法可靠配对时停止，列出候选让用户确认。

## 按指令选择模式

### 学习本次改稿

1. 确认两份稿件同源，并确认编辑稿确实由用户修改或明确认可。
2. 逐段对齐有意义的变化，分类为事实修正、任务特例、平台适配、结构调整、稳定表达偏好、观点立场或商业承接。
3. 保存差异证据；事实修正、具体观点、平台硬限制和单篇特例不得泛化为长期文风。
4. 更新已有候选的证据，不创建近义重复规则。
5. 单次改稿只能形成候选；用户没有明确确认长期规则时，不修改当前写作偏好。

### 确认候选偏好

只有用户明确指定候选编号或完整规则及适用范围时执行。

1. 核对候选、反例、冲突和适用范围。
2. 使用未参与提炼的真实内容做最小回归测试，只应用待测规则。
3. 测试通过后分配稳定正式编号；保留候选及历史证据并标记已升级。
4. 出现事实改变、信息丢失或机械套用风险时收窄规则，不静默升级。

### 停用正式偏好

只有用户明确指定正式规则时执行。将规则标记为停用，保存停用原因、日期、用户原始指令和替代规则；不删除历史，也不自动恢复近似规则。

## 硬边界

- 不修改、覆盖或重新润色 AI 初稿和用户编辑稿。
- 不用当前偏好反向改写旧稿。
- 不覆盖或删除旧证据、旧候选、旧正式规则和停用记录。
- 不把错别字、标点、名称、日期、价格或数字校正学习成文风。
- 不替用户编造修改原因，不从一篇内容猜测完整人格或文风。
- 候选偏好不参与正文生成；只有匹配当前平台和内容类型的启用规则可以执行。
- 用户本次明确要求、事实、用户观点、平台硬限制和产品边界高于历史偏好。
- 不发布、发送、上传或同步内容。

## 完成汇报

汇报配对稿件、有效修改数、分类统计、新增或更新候选、未进入候选的重要变化、冲突、待确认项和实际写入文件。

用户未确认长期规则时必须明确写：

> 本次只更新改稿证据和候选偏好，没有修改当前写作偏好。
