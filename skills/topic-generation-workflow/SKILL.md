# 可追溯选题生成

在当前工作区内执行，遵守工作区已有的代理说明和文件保护规则。完整读取 [选题生成合同](references/topic-generation-contract.md)。

## 先适配工作区

按优先级确定本轮素材集、历史选题和输出位置：

1. 使用用户明确给出的批次、目录、文件清单和输出路径。
2. 若项目有素材索引，从索引筛选指定批次或尚未处理的成功素材；常见位置包括 `02_爆款素材/素材索引.jsonl`。
3. 若没有索引，使用用户指定的素材目录；仍没有明确范围时，只在当前工作区中寻找语义清楚的“爆款素材”“高表现素材”目录。
4. 历史选题优先读取已有选题索引和候选报告；没有索引时按语义查找当前工作区中的选题文件。
5. 输出路径由用户指定；未指定时，标准模板使用 `04_选题库/{日期或版本}_选题报告.md`，其他项目使用当前工作区内已有的选题目录或新建 `选题库/`。

无法唯一确定素材集、素材集为空或存在多个同等可能的项目时停止，列出缺口，不跨项目猜测。

## 选择模式

- **首次或增量**：从明确的未处理素材集中新增候选。
- **重新审计**：完整复读指定素材集，只补充漏掉的母题或纠正被改味的候选，不复制已有候选。

## 完整读取与逐条去向

1. 列出本轮所有独立素材，并为每条确定稳定 `sourceId`；优先使用索引 ID，没有时使用不会冲突的文件标识。
2. 完整读取每条素材的正文或转写文本；只读标题、元数据、开头片段或抽样均不算完成。
3. 每条提取只属于该素材的正文要点、公共母题、核心吸引点、商业承接边界和去向。
4. 定位、历史选题、草稿和复盘只用于判断越界、账号适配与真正重复，不得强行把公共母题改成创作者个人角度。
5. 任一素材未读完或没有明确去向时停止并报告，不得宣称完成。

## 生成原则

- 先忠实提取公共母题与吸引点，再分析正文交付和商业承接。
- 原题可以成为候选；选题阶段不强制加入创作者观点、案例、产品或人设。
- 商业内容只标记边界，不能反过来改写前面的公共母题。
- 创作者自有素材不足只影响生产准备度，不取消有潜力的母题。
- 真正重复看核心问题、价值承诺、主要交付和使用场景；标题相似不等于重复。
- 不复制来源的完整结构、案例、原句、画面、数据或商业话术。
- 不设固定候选数量；有多少个通过门槛的独立母题，就如实输出多少个。

## 写入合同

只新建本轮指定的候选报告；文件已存在时停止，不覆盖。每个候选至少包含：

```markdown
## 选题 1：可以直接理解的公共母题

- 公共母题：
- 核心吸引点：
- 母题来源：原题直用／轻度归一／多素材归纳／评论补位
- 商业内容边界：无／具体说明
- 目标用户：
- 具体场景：
- 价值类型：
- 选题潜力分：X／100
- 生产准备度：可直接开始／需要补素材／待验证
- 素材状态：充足／一般／不足
- 待核实事实：
- 待补案例或观点：
- 建议：优先入选／可以入选／暂缓
```

报告必须包含“素材逐条去向审计”。每条源素材精确写一行：

```markdown
- 素材审计：<sourceId>｜完整正文已读：是｜正文要点：<该素材独有的一句话>｜公共母题：<母题>｜商业边界：<无或具体边界>｜去向：<独立候选／合并支撑／暂缓／淘汰>｜对应：<选题编号或具体原因>
```

不得漏项、重复 `sourceId`、使用“其他类似素材”等合并写法，也不得把未读完的素材标为“是”。

## 完成门禁

写入后回读并确认：

1. 审计行数等于本轮独立素材数，每个 `sourceId` 恰好出现一次。
2. 每条都有独立正文要点、母题、商业边界、去向和对应项。
3. 候选保留公共母题，没有因自有素材不足或商业正文被强行改味。
4. 来源路径真实存在，新增候选数量与报告总览一致。
5. 重新审计只补漏或纠偏，不重复已有候选。
6. 历史报告、用户决定、素材和草稿没有被覆盖、移动或删除。

若项目另有程序维护选题索引或处理状态，默认不直接修改这些机器文件；只有用户明确要求且项目合同允许时才交给对应程序刷新。

最终汇报素材范围、独立素材总数、完整阅读数、审计覆盖数、新增候选、合并支撑、暂缓、淘汰和报告路径。不生成正文，不总结爆款因果，不发布、不发送、不上传。
